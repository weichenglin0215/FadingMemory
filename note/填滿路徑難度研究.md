# 填滿路徑（一筆填滿、多色填滿）難度研究（V1.57.3.0 → V1.57.3.2）

玩家提供了兩款參考遊戲（block fill、multi-color fill），要新增兩款類似接電線、但**只有起點、終點要自己判斷**的遊戲，而且「要想出讓人類最難以解開的難度」。這份文件記錄：題目怎麼出、「難」怎麼量、怎麼用參考遊戲校準、題庫現況，以及要調難度時改哪裡。

> **改版經過**
> - V1.57.3.0：只用「解很少、模擬人類試走很多步」挑題。結果電腦鑽漏洞，多色填滿 140 題有 43 題「有一條路只有 1～2 格」。
> - V1.57.3.1：加上路長、轉彎比例、岔路口等「結構」限制，遊戲改成依 `[第一關, 封頂]` 參數挑題。
> - V1.57.3.2（現在）：玩家指出**難度不在轉角多少，而在 T 字／十字路口**，而且要站在人類的立場、看路上的每一格要做什麼判斷。所以「難」改用**人類視角模擬**（`FP.human`）來量，題庫整個重新產生，難度參數也換成路口、要猜的路口、陷阱、藏起來的終點。

## 1. 兩款遊戲

| | 一筆填滿（`blockfill`） | 多色填滿（`multifill`） |
|---|---|---|
| 棋盤 | 方格，有些位置是**空洞**（沒有格子） | 同左 |
| 起點 | 1 個，告訴你 | 2～4 個（每種顏色 1 個），告訴你 |
| 終點 | **不告訴你**：路最後停在哪一格，要自己判斷 | **每一條路的終點都不告訴你** |
| 過關 | 這條路走遍每一個格子 | 全部格子都被某一條路蓋到 |
| 數學上 | 找「從起點出發、經過每個格子剛好一次」的路（哈密頓路徑） | 把格子分成 k 條不重疊的路，每條從自己的起點出發 |

判定只看規則（每一格都蓋到、每條路都從自己的起點出發），所以跟出題時的解不同也算過關。

## 2. 為什麼不能直接隨機出題

隨機挖幾個洞、隨便放起點，幾乎都有**幾十到幾千種解**，亂走就走得出來。好的題目要「解只有一種、人類在路口很難選對」，這種題目只能讓電腦搜尋，所以做成**離線搜尋的題庫**（`js/fillpath_bank.js`）。遊戲出題時依難度參數挑一題，再隨機翻轉旋轉（8 種）。

## 3. 人類怎麼解（玩家的觀察）

1. **先找終點**：只有一邊跟別的格子相接的格子（死巷）一定是某條路的終點。多色填滿裡死巷比起點少，就有終點「藏起來」，玩家很困擾。
2. **只有兩邊相接的格子最好判斷**：進來一邊、出去另一邊，沒得選。
3. **T 字路口（三邊相接）最難**：不知道該走哪一條，也最容易出錯。而且 T 字不只出現在題目一開始，**走過的路會把旁邊的空格「變成」T 字**。
4. **十字路口**要看斜方向（右上、左上、左下、右下）有沒有格子。斜方向都沒有的話，只有一條路能穿過，另外兩邊會變成死巷，要靠斜方向的格子才接得起來。
5. **人會避免做出死巷**：畫線時避免讓空格只剩一邊相接。發現出現死巷就知道錯了，但**不一定知道該從哪裡改**。
6. 一筆填滿也可以把終點藏起來（題目上沒有死巷），但很難做：終點不標示，只要連成一線就過關，終點常常出現在意想不到的地方，反而變簡單。多色填滿也只能藏少數幾個終點。

## 4. 人類視角模擬（`FP.human`，js/fillpath_core.js）

沿著正確的解一步一步畫。站在路上的每一格，問三個問題：

- **ⓐ 路口**：前面有幾個方向可以走？2 個以上就是路口（T 字或十字，也包括「走過的路把旁邊變成 T 字」）。多色填滿還可以「在這裡結束這條路」，也算一個方向。
- **ⓑ 一眼看得出錯嗎**：走了之後，剛走過的地方有空格被完全圍死，或新線頭旁邊有 2 格「只能靠線頭進去」（不可能兩格都走到）。這些人一眼就看得出來。但「身後」的格子變成死巷，人常常沒注意到，所以不算一眼看得出。
- **ⓒ 細心想得出錯嗎**：再加上「全盤數死巷」。每個只剩一邊相接的空格都一定是終點，所以死巷不能比還在畫的路多。

好幾條路時，人會先畫「沒得選」的那條，所以每一步挑「一眼看不出錯的方向最少」的那條路。

每個「一眼看不出錯、但其實錯」的方向，再用搜尋量兩件事：**要試多少步才發現錯**，以及**最遠能走幾步才卡住**（陷阱深度）。

| 數字 | 意思 |
|---|---|
| `raw` 路口 | 路上前面有 2 個以上方向的格子數 |
| `dec`／`d3` | 一眼看不出錯的方向 ≥ 2（`d3`：≥ 3）的格子數 |
| `bits` | 這些路口的方向數相乘，取 log2（10 ≈ 1024 種組合） |
| `guess` 要猜 | 連細心的人（全盤數死巷）都還有 2 個以上方向的路口數 |
| `deep` 深陷阱 | 錯的方向裡，要走 3 步以上才卡住的個數 |
| `trap` 最深陷阱 | 錯的方向最遠能走幾步才卡住 |
| `hx` 人類試錯量 | 每一步算 1，加上每個錯方向「一半的機會先試到它 × 試多少步才發現錯」 |
| `vis`／`hid` | 一開始就看得出的終點數（死巷，起點不算）／藏起來的終點數＝路數 − `vis` |

另外 `FP.analyze` 量題目一開始的形狀：`t3` T 字格（三邊相接）、`x4` 十字格、`x4d` 斜方向也有格子的十字格、`lo`／`hi` 最短／最長的路。

## 5. 出題（離線搜尋，`test/reaction/gen_fillpath_bank.cjs`）

**模擬退火**：狀態是棋盤裡留下哪些格子，加上起點們（多色的起點數也可以增減）。一次改一點：開／關一格、換一對格子、移動一個起點、增減一個起點。區域一定要連成一塊。

分數（越接近 0 越好）＝
− |ln(1＋人類試錯量) − ln(1＋這一級的目標)|
− 0.4 × |ln(1＋解題器節點) − ln(1＋目標)|
− 2.5 × (解數 − 1)
− 3 × 結構違反程度

結構要求寫在 `PROF` 表，分三種強度：0 寬鬆、1 中等、2 嚴格。每項違反程度是「差多少 ÷ 門檻」：

| 項目 | 寬鬆 | 中等 | 嚴格 |
|---|---|---|---|
| 路口 ≥ 格子數 × | 0.30（一筆 0.25） | 0.38（0.32） | 0.46（0.40） |
| 要猜的路口 ≥ 格子數 ×（捨去） | 0.06 | 0.10 | 0.14 |
| 深陷阱 ≥ 格子數 ×（捨去） | 0.04 | 0.07 | 0.10 |
| 多色：藏終點 ≥（3 條路以上） | 0 | 1 | 1 |
| 多色：最短路 ≥ 平均路長 ×（至少 3 格） | 0.40 | 0.55 | 0.70 |
| 多色：最長路 ≤ 平均路長 × | 2.0 | 1.7 | 1.45 |

### 路跟路要交錯（V1.57.5，玩家回饋）

玩家發現：兩個起點的題目，兩條路常常完全沒有交錯，用一條直線就能把盤面切成兩半，兩條路各往自己那一邊走就過關。

量法（`FP.lineErr`／`FP.interlock`）：對每一條路，試各個角度（每 3 度）、各個位置的直線，把「這條路的格子」跟「其他格子」分開，看最少有幾格分到錯的一邊。`mix`＝各條路裡的最小值，`mixr`＝同一個數字除以較小那一邊的格子數（%）。解有好幾種的題目，取**所有解裡最容易切開的那一個**。

用舊題庫量：448 題多色裡有 335 題 `mix`＝0（一刀就切開），兩色的 50 題裡有 45 題。

出題時多色多了這兩個結構要求（跟下表一樣分三種強度，違反加重 3 倍）：

| 項目 | 寬鬆 | 中等 | 嚴格 |
|---|---|---|---|
| `mix` ≥（2／3／4 條路） | 2／1／1 | 2／2／1 | 3／2／2 |
| `mixr` ≥ %（2／3／4 條路） | 15／12／10 | 20／16／14 | 26／22／20 |

題庫**只收連「寬鬆」都合格、而且剛好 1 種解的題目**（解數 2～3 的只有在 1 種解的題目不到 20 題時才補）。每級的目標試錯量：第 0 級 12、1 級 30、2 級 70、3 級 150、4 級 300、5 級 600、6 級 1200、7 級 2400、8 級 4800、9 級 9000。第 4 級約等於參考題最難的一題（block 105，545）。

**第 10～12 級（V1.57.3.2 加的大棋盤）**：玩家把格子數封頂調到 72，所以再加 3 級：56～60 格（8×9）、61～66 格（8×10、9×9）、67～74 格（9×10、8×11），目標試錯量 8000／9000／10000——只是格子變多，沒有再往上翻倍。最大一級做唯一解很慢（多色只有 4 種顏色、每條路將近 18 格），所以一筆、多色各只有 20 題，其中約一半是 2～3 種解。遊戲挑到不是正方形的棋盤時，一律轉成直的（手機是直的，格子才大）。

## 6. 遊戲怎麼挑題（`FP.select`）

每一關先算出一組「想要的樣子」：每個參數用 `kit.ramp(level, 第一關, 封頂, RAMP_LEVELS)` 線性內插。人類試錯量 `HUMAN_EFFORT` 例外，取 ln 之後內插，所以是倍數式變化。

接著 `FP.select` 替題庫每一題打分：
- 評分 ＝ **違反程度 × 8** ＋ 離想要的格子數／試錯量／路數多遠；
- 違反程度 ＝ 每個「至少／最多」條件「差多少 ÷ 門檻」加總，加上解數超過上限的部分（每多一種扣 0.5；多色填滿用 `SOL_PENALTY`＝0.1，不然最大的棋盤因為大多不是唯一解，會一直輸給小很多的題目）；
- 在最好的前 6 題、而且評分不超過最佳＋1.0（V1.57.5 以前是 0.6）的題目裡，隨機挑一題（盡量不是上一題）。

條件太嚴、題庫裡沒有題目全部符合時，會挑「違反最少」的，不會卡住；瀏覽器主控台（F12）會印出「違反 x.xx」。用預設參數，兩款遊戲第 1～30 關幾乎都挑得到完全符合的題目。

## 7. 難度參數（每個都是 `[第一關, 封頂]`）

在各遊戲檔案最前面的「可以自己調的參數」。第 1 關用第一個數字，第 30 關用第二個，之後維持。

| 參數 | 意思 | 一筆填滿 | 多色填滿 |
|---|---|---|---|
| `TILES` | 格子數 | [10, 54] | [11, 52] |
| `COLORS` | 路（顏色）數 | — | [2, 4] |
| `HUMAN_EFFORT` | 人類試錯量（倍數式；參考題 24～545） | [12, 6000] | [12, 6000] |
| `SOL_MAX` | 解法最多幾種 | [3, 1] | [3, 1] |
| `HIDDEN_END_MIN` | 藏起來的終點至少幾個 | [0, 0] | [0, 1] |
| `HIDDEN_END_MAX` | 藏起來的終點最多幾個 | — | [0, 2] |
| `FORK_MIN` | **路口**至少幾個（路上前面有 2 個以上方向） | [2, 18] | [3, 26] |
| `GUESS_MIN` | **要猜的路口**至少幾個 | [1, 7] | [0, 8] |
| `FORK3_MIN` | 三岔路口（一眼看不出錯的方向 ≥ 3）至少幾個 | [0, 2] | [0, 3] |
| `DEEP_TRAP_MIN` | **深陷阱**至少幾個（錯的方向要走 3 步以上才卡住） | [1, 8] | [0, 8] |
| `TRAP_MAX` | 最深的陷阱最多幾步 | [12, 45] | [12, 40] |
| `T_CELL_MIN` | T 字格（三邊相接）至少幾個 | [2, 14] | [2, 10] |
| `CROSSROAD_MIN` | 十字格（斜方向也有格子）至少幾個 | [1, 4] | [0, 2] |
| `PATH_MIN` | 最短的一條路至少幾格 | （＝格子數） | [4, 9] |
| `PATH_MAX` | 最長的一條路最多幾格 | （＝格子數） | [14, 24] |
| `MIX_MIN` | 交錯程度至少幾格（0＝一條直線就能切開；V1.57.5） | — | [2, 2] |

調法舉例：
- 想要「每一關都有要猜的路口」→ 提高 `GUESS_MIN` 的第一個數字。題庫第 0 級（10～11 格）幾乎沒有要猜的路口，所以會改挑稍大的題目。
- 想要多色的終點更難找 → `HIDDEN_END_MIN` 調成 `[1, 2]`。
- 不想要「畫了大半張才發現錯」→ 降低 `TRAP_MAX`。

## 8. 限制

- 人類模型是簡化的：真人還會用其他視覺規則，而且「身後的死巷」有些人看得到、有些人看不到。第 9 級對真人到底多難，要靠玩家回饋。
- 題庫是有限的（每級 36 題，加上 8 種翻轉旋轉約 290 種樣子）。條件調得越嚴，符合的題目越少、重複越明顯。要更多題就搜尋久一點、`build` 時留更多題。
- 一筆填滿幾乎做不出「終點藏起來、又只有 1 種解」的題目（題庫裡 0 題）。
- 沒有提示功能。
