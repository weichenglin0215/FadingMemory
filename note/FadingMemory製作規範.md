# FadingMemory 製作規範（給 AI／開發者）

> 適用版本：1.1.0 起。修改本專案前請先讀完本文件；規則衝突時，以使用者當次的明確指示為準。
> 用語：**必須**＝不可違反；**建議**＝除非有理由，否則照做。

---

## 0. 專案一句話

長者記憶力練習網頁遊戲。三種模式：`quiz.html`（純 2D 題目）、`world.html`（Three.js 3D＋2D HUD）、`reaction.html`（3 選 1 反應力小遊戲）。主選單 `index.html`。全部是靜態檔案、傳統 `<script>`（不用 ES Modules，才能雙擊 HTML 開啟）。

---

## 1. 不可違反的原則

1. **必須** 讓手機與電腦呈現相同畫面：邏輯尺寸固定 **500×850（直式）**，由 `js/stage.js` 整體縮放。
2. **必須** 所有樣式取用 `css/theme.css` 的 CSS 變數（字體、字級、顏色、邊框、按鈕）。元件 CSS 不得寫死色碼或字級（3D 貼圖的 canvas 例外，見 §7.4）。
3. **必須** 每個畫面不需上下捲動就能看完題目、答案與按鈕。放不下時：先精簡文字 → 縮小間距 → 最後才用 `UI.fit()` 在變數規定的下限內縮字。
4. **必須** 氛圍開朗、健康、樂觀：宣紙淺黃底＋黃／綠／藍＋少量橘。不做深色主題、不用刺眼的紅（答錯用 `--c-bad` 暖橘紅）。
5. **必須** 文字大（一般介面 2 倍以上），最小字級不低於 `--fs-xs`（22px 邏輯像素）。
6. **必須** 使用繁體中文；對外文字不得宣稱醫療效果（不寫「預防失智」「治療」）。
7. **必須** 不引用 `screen_adaptive.*`（早期專案的參考檔）。
8. **必須** 每次發佈都把 `version.json` 的 `version` 加一，並在 `README.md`「版本更新紀錄」新增一筆。
9. **不可** 使用 emoji 當圖示（各平台長相不同，違反「畫面一致」）。圖示用 `UI.icon()`／`UI.art()` 的 SVG。

## 2. 檔案結構與載入

```
index.html / quiz.html / world.html / reaction.html  只放骨架 DOM＋設定 window.FM_PAGE，再用時間戳載入 js/boot.js
js/boot.js       讀 version.json，依 PAGES 清單載入 CSS/JS（加 ?v=版本號）
version.json     {"version","date","notes"}
css/theme.css    ★ 變數＋共用元件（.btn .opt .note .bar .screen .pill .card…）
css/stage.css    舞台與觸控規範
js/stage.js      Stage.init / onResize / rect / toLogical
js/ui.js         UI.h / fit / paginate / icon / art / fonts / store / ready
js/world/config.js ★ 3D 手感參數（鏡頭 pitchDeg、轉彎速度、NPC 速度、面向角度）
js/world/hud.js  kit.js  core.js  scenes.js  story.js
js/quiz_pools.js  quiz_gen.js  quiz.js   測試模式（題庫池／題目產生器引擎／畫面）
js/quiz_happyBirthday.js  quiz_travel.js  quiz_health.js   測試模式的三個主軸（各自完整撰寫 1～8 關）
js/menu.js  js/share.js   主選單（入口）／右上角分享按鈕（QR Code 彈窗）
js/reaction_core.js  reaction_speed.js  reaction_drop.js  reaction_spot.js  reaction.js
                 「秒反應」：共用引擎（登記清單／最佳紀錄）／三個小遊戲／進場控制（隨機挑選＋說明彈窗）
vendor/three.min.js   Three.js r158（UMD 版）
```

- **新增 CSS／JS 必須加到 `js/boot.js` 的 `PAGES`**，順序即執行順序（依賴在前）。
- 程式進入點一律用 `UI.ready(fn)`，**不可**直接掛 `DOMContentLoaded`（檔案是動態載入，事件可能早已觸發）。
- 3D 載入順序：`three → stage → ui → config → hud → kit → core → scenes → story`。
- Three.js 固定 r158 的 `build/three.min.js`（r160 起移除 UMD 版）。升級前必須改成可在 file:// 使用的方案並全面測試。

## 3. 版本與快取

- 版本號採 `主.次.修`：新功能加「次」，修正加「修」。
- boot.js 在 `file://` 讀不到 version.json 時，改用時間戳（本機無快取問題）。
- HTML 本身不含會變動的檔案清單，所以 HTML 被快取也不影響更新。

## 4. 舞台規範（2D＋3D）

| 項目 | 規則 |
|---|---|
| 2D 介面 | 全部放在 `#stage`（500×850），單位只用 **px**，不用 rem／em／vw／vh |
| 3D 畫布 | 放在 `#world`，**不在** `#stage` 裡；stage.js 把它擺在與 `#stage` 相同的螢幕矩形，畫布解析度 = 矩形 × dpr（上限 2）；相機長寬比固定 500/850 |
| 疊在 3D 上 | `#stage.stage--overlay` 本身不吃觸控；要點擊的元件加 `.hit` |
| 觸控 | 全站 `touch-action: pan-x pan-y`（禁止縮放）；只有搖桿與 3D 畫布用 `none`。**不可**寫 `touch-action: auto` |
| 座標 | 指標事件的 clientX/Y → `Stage.toLogical()` 或用元素 `getBoundingClientRect()` 換算 |
| 顯示／隱藏 | 用 `el.hidden = true/false`。已有全域 `[hidden]{display:none!important}`；**不可**用會蓋過 hidden 的 display 規則繞過它 |

## 5. 版面規範（不捲動）

- 標準結構：`.bar`（上方標題列，含返回鍵、標題、進度）＋ `.screen`（其餘高度，`overflow:hidden`）。
- 長文字（紙條）用 `UI.paginate()` 自動分頁；**必須先把同一畫面的按鈕列、提示文字放好，再分頁與縮字**（否則量到的高度是錯的）。
- 題目、選項用 `UI.fit(el, 上限, 下限, box)`；上下限取自 CSS 變數（`--fs-question`／`--fs-question-min` 等）。
- 置中的文字要用「內層元素＋box」模式量測（`UI.fit(inner, max, min, box)`）。
- 中文字型字身比行高高，量測容許 4px 誤差（`ui.js` 的 `TOL`），不可改成 0。
- 驗證：每關逐題檢查 `inner.offsetHeight <= box.clientHeight`、字級未低於上限、`#screen` 無溢出（手機 375×812 與電腦都要）。

## 6. 文字與題庫（測試模式＝題目產生器）

設計依據：`note/FadingMemory記憶混淆說明.md` 第 7～11 節（已和使用者確認）。

### 6.1 一局的規則
- 主選單按「測試模式」→ `menu.js` 設 `fm.quiz.fresh = true` → `quiz.html` 的 `QuizGen.session()` 產生新的一局（8 關全部），**整份內容**存在 `localStorage['fm.quiz.session']`。
- 一局之內（重玩同一關、重新整理、看完結果按「再玩一次」）內容不變。只有回主選單再進來才換。
- 存的是整份題目，不是只存種子：版本更新後，同一局的題目也不會變。**改了存檔格式要把 `quiz_gen.js` 的 `GEN_V` 加一**（舊存檔作廢）。
- 新的一局，每關的參數避開上一局這一關用過的值（`Gen.pick` / `Gen.num(…, key)` 會記下來）；左右轉這種二選一的用 `G.coin()`，純隨機、不記。
- `quiz.html?seed=數字` 可重現某一局。

### 6.1.1 故事主軸
- 每一局先挑一個主軸（`QuizGen.create` 會避開上一局的主軸），8 關都用同一個主軸，**不混用**。
- 主軸 = `QuizGen.addTheme({ id, name, names:[8 個關名], setup(G) → 整局共用參數 S, levels:[8 個 fn(G, S)] })`。
- `setup` 抽的是整局共用的參數（旅遊：3 個地點；看病：2 家醫院；生日：只有時間軸），讓同一個地點／醫院在不同關卡（1.9.0 起連第 1～4 關也一起）重複出現，製造跨關干擾。記錄在 `used.shared`，下一局同主軸會避開。
- 1.9.0 起，1～8 關**都由各主軸自己的檔案完整撰寫**，不再共用 `L1`～`L4`／`X`；三個主軸各自的第 1～4 關會用自己主軸的題庫池（例如看病用 `P.healthErrands1`、旅遊用 `P.travelErrands1`），內容要緊貼主軸，不能只是把公車／樓層／數量套個殼。
- 新增主軸：新檔案呼叫 `QuizGen.addTheme`，加到 `boot.js` 的 quiz 清單（`quiz_gen.js` 之後、`quiz.js` 之前）。改了存檔格式要把 `GEN_V` 加一（1.9.0 已改為 4）。
- 景點特色要寫成名詞片語（「看日出和神木的高山」），才能放進「那裡是＿＿」；原因要合乎常理（懸崖不會「休館」，要用「封路」）。

### 6.1.2 時間軸、角色名字、回想題（1.8.0）
- **時間軸**：`setup` 回傳 `S.tl`＝8 個 `{ today, ev }`（日期物件：`.s`＝「3月7日」、`.sw`＝「3月7日（星期六）」、`.w`＝「星期六」）。產生第 i 關前會設 `S.i = i`，關卡用 `S.tl[S.i]`。年份固定 2026、不寫出來，只拿來算星期幾。
  - 生日：`timeline(G, [4,10], [2,9])`，每關一個人在 `ev` 過生日。旅遊：`travelTimeline`，出發月份只用季節明確的月份（不用 3、6、9 月），8 關橫跨大半年。看病：`timeline(G, [3,9], [2,6])`。
  - **每一關紙條的第一句一定有「今天是○月○日（星期○）」＋時間**，並有具名角色。
  - 日期題工具：`G.dateQ`（誘答：前後一兩天、差一個禮拜、月日對調＋自訂）、`G.weekQ`、`G.daysQ`（還有幾天，要記兩個日期）、`G.wearQ`（日期→季節→衣服；季節對照：12～2 冬／3～5 春／6～8 夏／9～11 秋）。
  - 旅遊紙條**不可再出現「晚上很冷要帶外套」這類句子**，會讓衣服題變成兩個答案。
- **第 1～4 關的開場**：1.9.0 起沒有共用的 `X.head1/ctx2/head3/head4`，每個主軸的 1～4 關直接在自己的關卡函式裡寫開場白＋日期題（第一題設 `must`），不透過共用介面。
- **角色名字**：`applyCast` 在每一局開始時把 `P.home/kin/kids/relatives/grand` 換成「女兒淑芬」這種具名版本（原始稱呼在 `ROLES`）。程式裡**不可再寫死「孫子」「女兒」字串去比對**，要用 `otherGrand(g)`、`P.home.concat(P.kin)`。
- **回想題**：`RECALL = {5:[1], 6:[2], 7:[2,3], 8:[2,3,4,4]}`。8 關產生完後，`addRecalls` 從來源關卡的題目裡抽（不抽「一開始」題、優先抽題目文字不重複的），選項重新洗牌，插在第 2 題之後的隨機位置；題目多 `from`（來源關卡）。畫面上方明白標「第 N 關的回想題」（橘色標籤，1.11.0 起改成這個明講的寫法，不再讓回想題長得跟一般題目一樣）。
- 題數：4、6、8、12、17、21、26、36（`QuizGen.check` 會一併檢查回想題的來源）。
- 題庫池名稱不可重複：1.8.0 前看病的科別和百貨公司都叫 `depts`，後者被蓋掉；科別已改名 `clinics`。

### 6.2 檔案
- `js/quiz_pools.js`：題庫池（台北真實路名、地標、市場、百貨；東西都帶量詞 `{n, u}`；反常理顏色 `typ/odd`）。不含任何關卡內容，三個主軸共用。
- `js/quiz_gen.js`：只有引擎（`Gen`：可重現亂數、避開上一局、誘答工具；日期／角色名字／回想題／`QuizGen.lib` 共用工具；主軸登記 `addTheme`）。**不含任何關卡內容**。
- `js/quiz_happyBirthday.js`（`B1`～`B8`）、`js/quiz_travel.js`（`T1`～`T8`）、`js/quiz_health.js`（`H1`～`H8`）：生日、旅遊、看病三個主軸，各自完整撰寫 1～8 關，互不共用關卡邏輯。
- 題目格式：`{ q, t:題型標籤, o:[4], c:正解索引, k:[每個選項的混淆類型，正解為 null], w:[答錯時的說明], old:是否「一開始」題, from?:回想題的來源關卡, fromName? }`；關卡另有 `date`（那一關的「今天」）。

### 6.3 寫故事範本與出題的規則
- 紙條段落一段 ≤ 90 字（34px 大字一頁約 90 字）；第 1 關條列，第 2 關起口語文章，字數逐關增加。
- 故事裡**不用「他／她」**，一律寫稱呼（「隔壁黃阿姨說…」）。
- 量詞跟著東西走（一頂帽子、一條圍巾），不可寫死「一個」。
- 每題只有一個正解；誘答必須和紙條**明確矛盾**（例：紙條寫「黃色的蘋果」，不可拿「淡黃色」當誘答）。
- 同一件事只問一次；**一題的題目文字或正解，不可洩漏另一題的答案**（例：問了「在文具店要買什麼」，就不能再出「便條紙要買幾本」，要改問「在文具店要買幾本」）。
- 擾句（順口提到的內容）不可以被當成題目來問，只能變成誘答。
- 「一開始說的是？」題只在第 7、8 關，最多五分之一，題目要明講「一開始」。
- 誘答依優先順序列出（`L(值, 混淆類型, 說明)`），`G.q()` 會挑三個、盡量來自不同類型；說明省略時用預設句。
- 選項 ≤ 13 字（會自動縮字、最多兩行）；題目 ≤ 22 字。
- 失敗訊息語氣正向：「哎呀！…別擔心，從這一段重新開始。」

### 6.4 驗證（每次改題庫或範本後）
- 主控台：`QuizGen.check(QuizGen.create(任意數字).levels)` 回傳空陣列；並用迴圈跑 1000 局，確認沒有例外、沒有問題。
- 版面：`FMQuiz.question(關卡索引, 題目索引)`＋`FMQuiz.pick(錯的選項)` 逐題檢查題目、選項、答錯回饋都沒有溢出（見 §5）。
- 進測試模式（`quiz.html`）就會產生這一局，`js/quiz.js` 的 `logSession` 會把 8 關的紙條、每一題的選項與正解（含回想題的來源關卡）印在主控台（F12），不用另外呼叫，方便玩家或開發時直接核對。

## 6.5 水流特效（`js/waterflow.js`）——1.7.0 起停用、保留備用
- **目前沒有使用**：5→1 倒數引起玩家反彈，按「看完了，燒掉」後直接進入題目（測試模式）／直接繼續（正式模式）。
- 檔案保留，`boot.js` 不載入。要再用：把 `js/waterflow.js`、`css/waterflow.css` 加回 `PAGES`，再呼叫 `WaterNote.play()`。以下是它的設計紀錄。
- `WaterNote.play({ stage, note, onTick })` → Promise；測試模式與正式模式的紙條都用它。畫面開始模糊、切到題目時 resolve（約 6.4 秒），特效層 0.8 秒後自己移除（`WaterNote.TOTAL` = 7.2）。
- 時間軸：0.15 秒複製紙條 → 倒數 5→1，每個數字 1.25 秒（浮現 0.2 → 完整停留到 0.45 → 放進水裡、沿筆畫推水 0.45～1.0 → 水流平靜）→ 畫面模糊淡出。常數在檔案最上面。
- **數字一定要先完整、清楚地出現**：新數字先畫在顯示階段的最上層（`render(overlay, color)`，不經過流體），到 `T_TRACE0` 才在同一格拿掉最上層、寫進墨色場，畫面不會跳。若一出現就寫進墨色場，前一個數字留下的水流會立刻把它扭曲（1.6.1 的問題）。
- **直接擾動紙條**：瀏覽器不讓 WebGL 讀網頁像素，所以開始時用 `drawNoteReplica()` 把紙條複製到畫布：
  - 卡片（底色、左邊條、四角圓角、陰影）照 computed style 畫。
  - 每一個字用 `Range.getBoundingClientRect()` 取得確切位置，照原本的字型、大小、顏色畫。
  - 複本放進可被水流推動的浮點畫布（`page`，裝置像素解析度，上限 1100 寬，字才清楚），蓋在原本的位置後，再把 DOM 的紙條 `visibility:hidden`。
  - 之後每一格：速度場、墨色場（`ink`，會慢慢變淡）、紙條（`page`，不變淡只被推動）都做平流；顯示時墨色疊在紙條上。
- 流體管線與 `flower-moon/waterFlow.js` 相同：平流 → 散度 → 壓力 Jacobi → 梯度修正 → 潑濺 → 顯示；多了「蓋章」（把整個數字寫進墨色場）、「複製紙條」與「渦度強化」（curl → vorticity）。
- 筆刷照書寫筆順（`STROKES`，0～1 方框座標）沿筆畫推水，加一點左右擺動攪出漩渦；數字的圖和推水路徑用同一組筆畫。
- 不鋪底、不洗白：使用者明確要求「保留原本的紙條介面」「不要用半透明白色遮住前一個數字」。
- 調整手感（1.6.4 起是「稀的水」）：`VELOCITY_DISSIPATION` 0.12（越小越稀、推力越持久）、`PRESSURE_ITER` 24、`SPLAT_RADIUS` 0.0016、`CURL` 9（渦度強化，讓漩渦持續捲動往外帶；太大會失控）、`STIR_FORCE` 46（太大數字會糊成一團，試過 170）。`VELOCITY_CALM` 只用在新數字清楚停留的 0.45 秒，壓住殘留水流，數字放進水裡時才不會整個被沖歪。想要「濃稠」一點：調大 `VELOCITY_DISSIPATION`、調小 `CURL`。
- 只複製紙條本身；標題列、提示、按鈕是 DOM，不會被擾動（墨色可以流到它們上面）。
- 需要半浮點紋理；不支援就把數字直接疊在紙條上淡入淡出，節奏相同。分頁在背景時暫停。
- 驗證：`WaterNote.play({ stage, note, manual: true })` 後用 `WaterNote.last.step(秒)` 逐格推進再截圖。

## 6.6 秒反應（`js/reaction_*.js`、`reaction.html`）
- 引擎／內容分離，跟測試模式同一個做法：`reaction_core.js` 只提供 `Reaction.register({id, name, rule, mount})` 登記清單與最佳紀錄存取（`Reaction.getBest/setBest`，存在 `localStorage['fm.reaction.best.<id>']`），**不含任何遊戲內容**；三個小遊戲檔案各自呼叫 `Reaction.register` 登記自己；`reaction.js`（進場控制，必須最後載入）才在 `UI.ready` 裡從 `Reaction.list()` 隨機挑一個、顯示說明彈窗、呼叫 `game.mount(screen, {setMeta})`。
- **載入順序很重要**：`reaction_core.js` 必須在三個遊戲檔案之前、`reaction.js` 必須最後——`reaction.js` 的 `UI.ready(fn)` 若在文件已載入完畢時呼叫會立刻同步執行 `fn()`，若清單還沒登記完就會抽到空清單。`js/boot.js` 的 `PAGES.reaction.js` 陣列順序＝執行順序，跟 `quiz_gen.js → 三個主軸 → quiz.js` 是同一個道理。
- 每個小遊戲的 `mount(container, ctx)` 自己管理整個生命週期（畫面、重玩、分數），`ctx.setMeta(text)` 更新上方列右側文字（通常顯示最佳紀錄）。返回主選單一律用整頁導覽（`location.href='index.html'`），不做 SPA 切換。
- 說明彈窗（`.rule-dlg`）只在**進頁面第一次**顯示，看完「開始挑戰」才 `mount`；右上角「?」可以隨時重看規則（不影響進行中的遊戲，因為彈窗只是蓋在畫面上）。
- 配色：白底／黑格／紅／黃／紫等是遊戲二（神準落下）的**功能色**，不是隨意選的——直接沿用專案既有色票（`--c-card` 當白底、`--c-ink` 當黑、`--flow-ink-1` 當紅、`--c-yellow` 當黃、`--flow-ink-5` 當紫），沒有新增任何色碼，維持整體美術風格一致。遊戲三（大家來找碴）的方格顏色本質上是隨機 HSL（色彩知覺測試需要），不受主題色票限制。
- 遊戲二的精準判定是**遞迴九等分**：9 格（1234-5-4321，中間紅）→ 插中紅色再細分 9 格（8 紅 1 黃）→ 插中黃色再細分 9 格（8 黃 1 紫）。同一次落下的水平座標，依序對 9 取模／整除即可算出三層的格子索引，不是三次獨立判定。
- **遊戲二（1.12.1）：結果在按下「落下」那一刻就先算好**——尺左右反彈的位置是純函式 `bouncePos(start, dir, speed, t, max)`（輸入經過的時間，回傳位置；用三角波公式 fold 處理反彈與負時間，不用逐格累加），按下當下就用同一個函式算出「落地那一刻」的位置與三層格子索引；畫面上的下落動畫只是把同一組結果重新演一次（每一影格呼叫同一個函式），保證看到的落點跟算出的結果一定一致。
  - **重力**：三角形的 `top` 用 `start + (target-start) * p * p`（`p` = 經過時間 / 總時間）驅動，不用 CSS transition——位置 ∝ 時間平方＝等加速度，一開始慢、越落越快；之前用 CSS transition＋`transitionend` 事件判斷落地，這個事件在某些情況下不會觸發，改成每一影格自己算位置後，`transitionend` 的問題解決了，但「按了常常沒反應」還是會發生——**真正的關鍵原因是 `requestAnimationFrame` 本身**：瀏覽器會在分頁切到背景、視窗被蓋住、省電模式等情況下直接暫停整個 `requestAnimationFrame`（不是變慢，是完全不再執行），按鈕按下去那一刻已經 `disabled`／隱藏了，`frame()` 卻可能永遠不會再被呼叫，遊戲卡在半空中。**修正：`setTimeout(land, FALL_MS + 400)` 當安全網**，時間到了不管 `requestAnimationFrame` 有沒有正常跑完，都強制呼叫同一個 `land()` 判定落地（`landed` 旗標防止重複觸發）；`setTimeout` 是獨立於畫面渲染的計時器，同樣情況下最多被延後執行，不會被整個停掉。用「完全停用 `requestAnimationFrame`」模擬最壞情況驗證過：遊戲仍會在時間到了之後正常跑完，不會卡住。這個安全網的邏輯也適用在其他地方新增靠 `requestAnimationFrame` 推進的遊戲流程時，別只靠它，一定要加計時器保底。
  - **落下時間與尺的速度要互相配合**：尺速度是為了「反應力遊戲要看得出移動」而定的（不能太慢），但落下時間如果太長，不管尺多快，落下期間尺都會移動超過好幾格，變成怎麼按都插不到中間。目前 `FALL_MS = 380`、尺速度 60～130 px/s，落下期間尺大約移動 1～3 格，插中紅色是靠算時機做得到的，不是純運氣。這兩個數字要一起調，不能只改其中一個。
  - **接觸點＝畫面放大的錨點，且永遠不動**：三角形是 `.drop-field` 的直接子元素（不在會被縮放的 `.drop-zoom-root` 裡），固定在畫面上同一個像素位置；`.drop-zoom-root` 的 `transform-origin` 設成接觸點的座標，之後只改 `transform: scale()`，數學上錨點座標必定原地不動（可以用一個放在 zoom-root 外、座標固定的 marker，縮放前後量 `getBoundingClientRect()` 驗證：位移一定是 0）。三角形因此「釘住不放」，玩家看到的是鏡頭往同一點持續拉近，不是切換到另一張畫面。
  - **落點在尺的範圍外＝真的插空了**，不能夾到最邊上那一格冒充插中（那樣會誤導玩家「按這裡總會插中什麼」）；`computeOutcome` 判斷 `localX` 是否落在 `[0, stripW)`，不在範圍內就回傳 `{ miss: true }`，直接顯示「插空了」，不進放大流程。
  - **按鈕置中不能用 `left:50%+transform:translate(-50%,-50%)`**（1.12.3 修正）：`.btn:active{transform:scale(0.97)}`（`theme.css`，全域）的 specificity（class+pseudo-class）比 `.drop-btn`（單一 class）高，同一個 `transform` 屬性只會留下優先度較高的那個，不會疊加——手指一按下去，置中用的 translate 整個被蓋掉，按鈕瞬間往右下角跳開半個按鈕的寬高（140×72 就是跳 70×36px），跳出手指原本按著的範圍，變成「按了沒反應」。改成用 `.drop-field { display:flex; align-items:center; justify-content:center; }` 置中，`.drop-btn` 不再用 `transform` 定位，`transform` 這個屬性就只剩 `:active` 的縮放在用，不會再互搶。**任何用 `transform` 置中的可點擊元件，只要它或其父層可能有 `:active`／`:hover` 也去動 `transform`，都要檢查這個坑**——驗證方法：對元件送一個真的 `mousedown` 事件（純改 class 沒辦法觸發 `:active` 偽類），比較送之前跟送之後的 `getBoundingClientRect()`，位移應該是 0。
  - **判定要用 `pointerdown`，不要用 `click`**（1.12.3 修正）：這是「算準時機」的遊戲，`click` 在觸控裝置上要等手指離開螢幕（`touchend`）才觸發，玩家看準時機按下去的那一刻，跟遊戲真正判定的時間點會差了手指按著不放的時間，時機全部算錯。改用 `pointerdown`（手指一碰到螢幕就觸發，滑鼠／觸控／筆通用），並在 handler 裡 `e.preventDefault()`（同一個按鈕之後可能還會再收到瀏覽器補發的相容 `click`，但按鈕這時候已經 `disabled`，原本的 guard 就會擋掉，不會重複觸發）。
- 遊戲一（1.12.1 起）畫面與結果一律顯示**秒**（`X.XXX`，小數點後三位），不用「毫秒」這個詞——內部計時仍用 `performance.now()`（不是 `Date.now()`）以毫秒整數比大小（precise、無浮點誤差），只有顯示才換算成秒；倒數畫面在剩餘時間 > 3.000 秒才顯示數字，之後刻意留白讓玩家自己默數。判定也在 1.12.3 改成 `pointerdown`，理由跟遊戲二一樣（用 `click` 會多算手指按著不放的時間）。
- 遊戲三（大家來找碴）的差異**隨關卡線性遞減**（`start - step*(level-1)`，碰到 `floor` 就不再變小），不是等比例縮小（乘某個 <1 的係數）——等比例縮小前幾關降得快、十幾關後幾乎不再變難，很快卡在下限；線性遞減才會每一關都確實比上一關更難一點點。色相／飽和度／亮度三個頻道分別校正 `start/step/floor`，讓下限落在差不多的關卡數（目前約第 19～20 關），同一關不管抽到哪個頻道，難度感受接近。底色的飽和度／亮度刻意收在中段（52～68％／44～60％），避免抽到太淡或太暗的底色時，色相差異變得幾乎看不出來，導致難度失控。
  - **色相差異要用「繞圈最短距離」算，不能直接 `|a-b|`**（1.12.3 修正）：色相是 0～360 度的圓，345 度跟 23 度只差 38 度（繞 0/360 這條近路），直接 `|345-23|=322` 會在跨過 0／360 的地方算出離譜的超大差異，跟畫面上實際看到的差異程度對不起來。`hueDiff(a,b) = d>180 ? 360-d : d`（`d=|a-b|%360`）；飽和度／亮度是 0～100 的直線刻度，`Math.abs` 本來就是對的，不用這個處理。
  - 驗證用（兩層）：`mount()` 一開始呼叫 `logLevelTable()`，在主控台印出第 1～21 關「正常格」與「差異格」各自的 H／S／L 與差異量（`console.table`），方便看難度曲線的**趨勢**，但這是另外獨立抽樣，顏色不會跟畫面上實際玩到的相同；`round()` 裡另外印出**這一關實際顯示在畫面上的**那一組真實數值（同一個 `diffRow()` 把兩處算法統一），要核對「螢幕上這格顏色到底差多少」要看這一個，不是開頭那張表。

## 7. 3D 規範

### 7.1 座標慣例
- 單位公尺；y 向上；角色正前方 = `(-sin(yaw), 0, -cos(yaw))`，yaw = 0 時面向 **-z（北）**；往右轉 = yaw 變小。
- `K.box(parent, x, y, z, w, h, d, color)`：x、z 為中心，**y 為底部**。
- `K.wall(ctx, x0,z0, x1,z1, h, color)`：單面牆，朝向「從起點走到終點時的右手邊」。房間用 `K.room()`（自動朝內）。
- 室內牆**必須**是單面（鏡頭在牆外時自動看穿），並用 `K.wall`／`K.room` 建立（會自動登記成遮擋物，擋住視線時變半透明，見 §7.6）。電梯門、壁畫等貼在牆上的東西也用單面平板，不用方塊。

### 7.2 場景（`scenes.js`）
```js
FM.scenes.xxx = {
  build: function (ctx, K, api, params) { ... },   // 蓋場景
  enter: function (ctx, api, params) { ... }       // （選用）進場後的演出
};
```
- `ctx.place` 地名、`ctx.spawn {x,z,yaw}`、`ctx.bounds`、`ctx.walkable()`（網格城市用）、`ctx.block()` 碰撞、`ctx.zone()` 觸發區、`ctx.item()` 互動物件、`ctx.tick()` 每幀更新、`ctx.occluder()` 會淡出的遮擋物、`ctx.cam { distance, ahead }` 鏡頭覆寫。
- 出生點**必須**不在碰撞區內，且鏡頭後方不能緊貼實心物件（例如電梯門框）。
- 可走區（walkable）相接處**必須重疊**至少一個角色半徑以上，否則走不過去（例如巷子的 x0 要伸進主路）。
- 「走錯路」觸發區要離路口 7～13 公尺，給玩家反悔空間。
- 每次 `api.go()` 會自動存檢查點；失敗時 `api.fail(原因)` 會回到最後檢查點並還原當時的隨身物品。

### 7.3 互動物件（`ctx.item`）
| 欄位 | 規則 |
|---|---|
| `label` | **動詞**、4 字內：搭電梯、等公車、開門、按門鈴、進店、買東西、取蛋糕、租單車、說話 |
| `x, z, r` | 玩家站的位置與半徑（2.2～3.2） |
| `fx, fz` | **物件本身**的位置：面向判斷與標記都用它。必須設定在物件上（門、站牌桿、店員） |
| `y` | **標記頂端**高度：招牌物件 = 招牌下緣；人物 = 頭頂上方約 2.75 |
| `hit` | 可點擊的 3D 物件（點擊只檢查距離） |
- 互動鍵只在「距離 ≤ r 且面向夾角 ≤ `FM.CONFIG.faceAngleDeg`」時出現。

### 7.4 招牌與文字貼圖
- 一律用 `K.sign()`／`K.textTex()`（canvas，網路字型載入後自動重畫；同場景同字同色共用貼圖）。
- 招牌平面的寬高比由 `sw/sh` 決定，canvas 會自動配合，不會變形。
- **桿子只能到招牌下緣**，不可穿過招牌擋字。
- 雙面招牌用 `both: true`（兩片背對背的平面），不要用 DoubleSide（背面字會左右相反）。

### 7.5 效能預算（手機）
- 每場景 draw calls 建議 ≤ 150（`FM.debug.info().calls`）。
- 大量重複物件**必須**用 InstancedMesh：樹 `K.forest()`、路面標線 `K.stripes()`、雲 `K.clouds()`。
- 建築本體 = 1 個 mesh（`facadeGeo` 把窗戶重複次數寫進 UV）。
- 不開陰影貼圖；角色、車用 `K.blob()` 假陰影。
- 共用幾何體 `K.G.*` 與快取材質 `K.mat()` 不可 dispose；場景專屬的貼圖、材質、幾何體**必須** `K.own()`，換場景時自動釋放。
- 每幀不可 new 物件（Vector3 等請重用）。

### 7.6 避免閃爍與遮擋
- **不可**讓兩個面在同一平面重疊（z-fighting）。貼附物至少離 0.01～0.03；地面層用不同 y（草地 -0.05、人行道 0.004、路面 0.012、標線 0.016）。
- 公車頂的色帶頂面必須低於車頂（已修正過一次）。
- 視線遮擋有兩層機制（`core.js`），每幀從角色的胸口（1.2m）與頭頂（1.95m）各拉一條視線到鏡頭：
  1. **登記的遮擋物** `ctx.occluder(mesh, group)`：平滑淡出成半透明，`group` 內其他附屬裝飾隱藏。建築本體、店面隔間、每一面牆（`K.wall` 自動登記）都用這個；這類 mesh 必須有**自己的材質**（`K.own(new MeshLambertMaterial…)`）。
  2. **其他所有 mesh**：自動檢查，擋到時暫時換成共用的半透明材質複本，不擋 0.25 秒後換回。人物（有 `userData.parts` 的群組）整個一起變淡。地面平板（`K.G.ground`／`K.G.circle`）、InstancedMesh、互動標記不參與。
- 射線必須**雙向**各打一次：單面牆只有正面打得到（鏡頭在正面那側時要從鏡頭打向角色）；建築方塊在鏡頭位於內部時要從角色打向鏡頭。
- 新增的大型物件不用特別處理就會自動淡出；但若是**場景建好之後**才動態加入的（例如進站的公車），不會被列入檢查。
- 天空球半徑必須小於相機 far（目前 200 < 230）。

### 7.7 鏡頭與手感（`js/world/config.js`）
- `camera.pitchDeg`：往下看的角度（預設 12）。**不可**在場景裡寫死鏡頭高度；場景只能覆寫 `distance`、`ahead`，特殊演出用 `FM.core.camTo()`。
- `controls.turnWalk / turnBike`：轉彎速度（已放慢為 33%，避免 3D 暈）。
- `npcSpeed`：路人速度（200%）。

### 7.8 劇情 API（story.js 提供給場景）
`ask(opts)`、`say(opts)`、`toast(text, ms, {silent})`、`banner(text)`、`place(text)`、`freeze(bool)`、`give(k)`、`has(k)`、`go(sceneId, params, {text, checkpoint, hold})`、`fail(reason)`、`win()`、`sfx(name)`、`speak(text)`。
- 演出前 `api.freeze(true)`；`api.go()` 結束時會自動解凍。
- 對話一律走 `api.ask/say`（大按鈕、會暫停移動），不要自己做 DOM 對話框。
- **劇情裡的等待一律用 `FM.core.wait(ms)`／`FM.core.tween()`（遊戲時間）**，不可用 `setTimeout`、`UI.wait`：
  遊戲時間在暫停、切到背景時會停住；換場景後，舊場景還沒跑完的 wait/tween 會作廢（不 resolve），舊劇情流程不會跑進新場景。
  （例外：`go()` 裡的轉場淡入淡出用 `UI.wait`，因為那時 `busy`，選單打不開。）

### 7.9 暫停
- `FM.core.paused = true` 時，`frame()` 只畫圖、不呼叫 `update()`：玩家、路人、公車、補間、等待、時鐘全部停住。
- 暫停由 story.js 的 `setPaused()` 管：同時暫停語音（繼續時重念被打斷的那一句）、`AudioContext.suspend()`、把暫停時間從「花了幾分鐘」扣掉。
- 暫停和 `freeze` 是兩件事：暫停**不碰** `frozen` 和搖桿，繼續時原樣接回。
- 暫停中 `api.ask/say` 會等到繼續後才出現。
- 「重來這一段」：保持暫停直到 `go()` 載入新場景（舊劇情隨換場景作廢）才解除。
- 頁面切到背景（`visibilitychange`）時自動打開暫停選單。

### 7.10 語音朗讀（story.js 的 `Voice`，接在 `HUD.voice`）
- 自動念：對話框（標題＋內文）、紙條（每翻一頁念那一頁）、提示 toast、轉場的黃底字。公車到站廣播用 `api.speak()`。
- 對話框可給 `speak: '要念的字'` 覆寫（例如「下午 5:00」要念成「下午五點」），或 `speak: false` 不念；toast 用 `{silent: true}` 不念。
- 念的內容排隊；對話框／紙條的語音跟著畫面（關掉就停）；其他語音排超過 3.5 秒（轉場字 6 秒）還輪不到就跳過，避免過站了才念。
- 念之前會轉換寫法：`5:00`→5點、`3F`→3樓、`UBIKE`→U bike、換行→句號；長段落切成 40 字以內的短句（有些瀏覽器念太長會被截斷）。
- 瀏覽器規定頁面被點過一下之後才能發聲：所以開場是「回家的路」標題卡（按開始），說明放在第二張才念得出來。
- 測試模式（quiz.html）目前**不**念。
- 驗證語音：在主控台把 `speechSynthesis.speak` 換成記錄文字＋假裝念完（`setTimeout(() => u.onend(), 150)`），就能檢查念了哪些句子。

## 8. 驗證流程（每次修改後）

1. `python -m http.server 8743`（或 Preview 的 `fading-memory-static`）。
2. 主控台不可有錯誤（Three.js 的 r150+ deprecation 警告可忽略）。
3. 3D：用 `world.html?scene=xxx&inv=gift,cake` 直接進場景；`FM.debug.walk(x, y, 秒)` 用**固定時間步長**移動。預覽視窗在背景時瀏覽器會降低 requestAnimationFrame 頻率，不可依賴即時動畫做判斷；劇情等待是遊戲時間，也要用 `FM.debug.step(秒)` 推進（`await` 一下再 step，讓前一段 Promise 先接上）。`FM.debug.menu()` 打開暫停選單。
4. 截圖前先 `FM.debug.step(0.5)`，再等約 1 秒（背景視窗的畫面合成會延遲，太快截到的是舊畫面）。
5. 手機（375×812）與電腦兩種尺寸都要看；2D 測試模式跑自動逐題溢出檢查（§5）。
6. 每個錯誤路線（搭錯車、走錯樓層、走錯巷子…）至少觸發一次，確認回到正確檢查點。

## 9. 踩過的坑（不要再犯）

| 問題 | 原因 | 正確做法 |
|---|---|---|
| 所有面板同時顯示 | `.panel{display:flex}` 蓋過瀏覽器內建的 `[hidden]` | 全域 `[hidden]{display:none!important}` |
| 紙條最後一行被切掉 | 分頁時按鈕列還沒放 | 先放按鈕再分頁 |
| 選項字被縮到最小 | 中文字身比行高高，scrollHeight 永遠大一點 | 用 box 量測＋4px 容許誤差 |
| 角色背對建築時看不到 | 鏡頭在建築裡，店面裝飾擋住 | occluder 的 group 一併隱藏 |
| 標記巨大擋畫面 | 標記在鏡頭與角色之間 | 比角色更靠近鏡頭就隱藏 |
| 3F 出生看不到角色 | 電梯門框是實心方塊 | 牆上物件用單面平板 |
| 天空消失 | 天空球比相機 far 大 | 半徑 < far |
| 巷子走不進去 | 可走區只相接沒重疊 | 可走區要重疊 |
| 桿子擋住招牌字 | 桿子穿過招牌 | 桿子只到招牌下緣 |
| 程式沒啟動 | 動態載入後才掛 DOMContentLoaded | 用 `UI.ready()` |
| 走進電梯間看不到角色 | 辦公室與走廊之間的單面牆面向鏡頭，從角色打出的射線打不到它的背面 | 視線射線雙向各打一次，所有牆都登記為遮擋物 |
| 角色完全不能動 | 新變數 `blocked` 和碰撞函式 `blocked()` 同名，把函式蓋掉了 | core.js 是一個大閉包，新增變數前先搜尋有沒有同名的函式 |
| 暫停選單開著，公車還在跑、跳出「到站了」；按「下車」後搖桿消失 | 暫停只是一個對話框＋`freeze`，劇情用 `setTimeout` 照樣往下走；關選單時又把舊的 `frozen` 狀態蓋回去 | 真正的暫停 `FM.core.paused`（§7.9）；劇情等待用遊戲時間；暫停不碰 `frozen` |
| 開場說明沒有聲音 | 瀏覽器不准還沒被點過的頁面發聲 | 先放一張要按「開始」的標題卡 |
| 改了 JS 但瀏覽器跑的還是舊檔 | 版本號沒變，`?v=` 一樣，瀏覽器用快取 | 改了檔案要發佈就加版本號；本機測試卡在舊檔時，也先加版本號 |
| 故事寫出「一個帽子」 | 量詞寫死 | 題庫池裡每樣東西都帶量詞 `u` |
| 產生器偶爾失敗（誘答不足） | 數字範圍太小，或多個誘答剛好等於答案 | 每題多列幾個備用誘答；`near()` 會補 ±1～±3；跑 1000 局驗證 |
